<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Phone browser → `POST /api/ingredients`, `POST /api/categories` | First write path in the project — untrusted, unauthenticated JSON bodies now mutate the source-of-truth database. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-08 | Tampering | `POST /api/ingredients` body | high | mitigate | `schema.body` is the shared `ingredientInput` Zod object enforced by `@fastify/type-provider-zod` before the handler runs; unknown fields are not persisted and Drizzle emits parameterized SQL for the insert. |
| T-01-09 | Denial of Service | `POST /api/ingredients`, `POST /api/categories` | medium | mitigate | Zod `.max()` bounds (name 200, note 200, category name 60) reject oversized payloads at the boundary; the client mirrors them as `maxLength` so the common case never reaches the network. |
| T-01-10 | Tampering | `categoryId` referencing a nonexistent category | medium | mitigate | FK RESTRICT plus the `foreign_keys = ON` pragma reject the row at the database; the route translates the constraint error into a 400 rather than a 500, so failure detail is bounded and no stack trace escapes. |
| T-01-11 | Information Disclosure | Constraint-error responses | low | mitigate | Unique- and foreign-key violations are caught and replied to as fixed 409/400 messages; raw SQLite error text and stack traces are never returned to the client. |
| T-01-04 | Spoofing | Unauthenticated writes | medium | accept | Unchanged from plan 01-01: LAN-only, trusted-household access is a documented project-level decision. Now carries write impact, which the decision already anticipated. |
</threat_model>

  hand-crafted request can produce one.
