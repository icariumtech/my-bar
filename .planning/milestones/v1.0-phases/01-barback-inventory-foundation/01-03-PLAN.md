<objective>
Deliver the Barback screen's signature interaction: the owner swipes a bottle row to mark it out of stock or back in, with a brief undo window before anything is committed to the server.

This is the interaction the owner performs most often while restocking, and it is the one place where the inventory's trustworthiness is created or lost — every later screen's makeable/not-makeable answer derives from the `in_stock` value this task writes.

Purpose: close INV-03 with the exact gesture and safety model the owner chose (D-08, D-10).
Output: a stock-toggle endpoint and a swipeable row with a deferred commit and undo.
</objective>

  <action>
    Add `useToggleStock()` to `src/api/useIngredients.ts`, a TanStack Query mutation sending
    `PATCH /api/ingredients/:id/stock` with an `inStock` boolean body. Invalidate `['ingredients']` in
    `onSettled` so the list reconciles to server truth whether the request succeeded or failed. On failure, show
    an antd toast reading "Couldn't update stock — try again." and let the invalidation restore the row's real
    state — do not hand-roll a rollback, since the refetch already yields the authoritative value.

    Create `src/components/IngredientRow.tsx` exporting `IngredientRow`, taking the ingredient and an
    `onCommitToggle(id, nextInStock)` callback. Use `useSwipeable` from react-swipeable with `onSwipedLeft`
    starting a toggle to out-of-stock and `onSwipedRight` starting a toggle to in-stock — that direction mapping
    is fixed by D-08 and by the owner's explicit restatement of it, so do not invert or make it configurable.

    The commit must be DEFERRED, and this is the crux of the task. Starting a toggle sets a local `pending`
    state holding the target boolean and starts a timer of 3000ms held in a ref; only when that timer elapses is
    `onCommitToggle` invoked and `pending` cleared. An "Undo" control shown while `pending` is non-null clears the
    timer and resets `pending`, and in that case no network request is ever made. Three shapes are explicitly
    ruled out by D-08 and D-10 and must not be built even as an interim step: a toggle switch control, a
    whole-row tap target, and firing the request immediately with a reversal offered afterwards. The last one is
    the subtle trap — an immediate write with a compensating undo produces two round-trips, a window where the
    Patron screen would read a value the owner is about to retract, and a failure mode where the compensating
    write is the one that fails. Clear the timer in a cleanup effect on unmount so a row scrolled out of the
    list mid-window cannot fire against an unmounted component.

    Render the displayed stock state as `pending` when a toggle is in flight and the ingredient's server value
    otherwise, so the row flips instantly on swipe. Show the row on the secondary surface with the accent color
    for in-stock and the destructive color for out-of-stock per the UI-SPEC Color contract, dimming the
    out-of-stock row. Reveal the destructive background behind the row as the swipe progresses using a CSS
    transform, which is the visual half of the gesture react-swipeable does not provide. The row is at least
    48px tall and the Undo control is itself at least a 48px tap target, per D-13 and the UI-SPEC spacing
    exception. Truncate a long bottle name to one line with a CSS ellipsis rather than wrapping, so row height
    stays uniform and the list stays scannable one-handed. Do NOT show a confirmation dialog at any point — per
    D-10 the undo window is the entire safety net.

    Update `src/components/IngredientList.tsx` to map each ingredient to an `IngredientRow`, passing a commit
    handler backed by `useToggleStock()`. Also give the row an edit affordance — an antd icon button using
    `@ant-design/icons` — that calls an `onEdit(ingredient)` prop the list threads through; plan 01-04 wires that
    prop to the edit form, so for now the list may leave the handler undefined and the row must simply not render
    the control when no handler is supplied. Keep the swipe handlers off that button so tapping it never starts
    a toggle.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Phone browser → `PATCH /api/ingredients/:id/stock` | Untrusted path param and body mutate the single field every future screen's makeable calculation reads. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-12 | Tampering | `PATCH /api/ingredients/:id/stock` body | high | mitigate | `schema.body` is the narrow `stockPatch` contract (a single boolean), so a toggle request cannot rename a bottle or reassign its category even if the client is compromised or buggy. Drizzle's builder emits a parameterized UPDATE touching only `in_stock`. |
| T-01-13 | Tampering | `:id` path parameter | medium | mitigate | `schema.params` constrains `id` to a uuid string, rejecting malformed ids at the boundary before any query is constructed. |
| T-01-14 | Repudiation | Silent no-op toggle | medium | mitigate | An unmatched id returns 404 rather than a success. A swipe that reports success while writing nothing would leave the Patron screen confidently wrong, which is the exact failure the project's core value forbids. |
| T-01-15 | Denial of Service | Rapid repeated swiping | low | accept | Each row's commit is debounced behind its own 3000ms grace timer and an undone swipe sends nothing, so the gesture cannot generate a request per swipe event. LAN-only single-owner use makes deliberate flooding out of scope. |
| T-01-04 | Spoofing | Unauthenticated stock writes | medium | accept | Unchanged from plan 01-01: LAN-only trusted-household access is a documented project decision. |
</threat_model>

## Planner Assumptions

- **3000ms is the concrete reading of D-08's "brief (~few seconds)".** `01-RESEARCH.md` assumption A4 flags this
  as a tunable constant rather than a structural choice. Keep it a named constant and confirm the feel with the
  owner during UAT — it is a one-line change.
- **Concurrent toggles are last-write-wins.** No row versioning exists. The `onSettled` invalidation means both
  devices converge on the winning value after the next refetch.
- **An out-of-stock row stays in the list** rather than being filtered out; the owner needs to see what is out in
  order to restock it. Filtering by stock state is not requested by INV-04 and is not built.
- **No component test framework is selected for this phase** (`01-RESEARCH.md` Validation Architecture), so the
  gesture and timer behaviour is verified by a scripted human check plus source assertions. If gesture
  reliability proves poor on iOS Safari, `@use-gesture/react` is the documented escape hatch (RESEARCH A2).
