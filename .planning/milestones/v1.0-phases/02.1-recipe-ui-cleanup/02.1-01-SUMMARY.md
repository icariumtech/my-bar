## Decisions Made

- **Checkpoint D-31 resolution: option-a (full replacement).** The checkpoint task presented a choice between fully replacing `recipe.makeable: boolean` with `recipe.overallStatus: TriStateStatus`, versus keeping both fields as a transitional shim. The plan's own task 1 action text already stated "per the checkpoint decision (option-a)" — the planner had pre-resolved this during planning. Per the parallel-execution instructions ("if the plan's checkpoint task already documents the resolved decision inline... follow the plan's documented resolution directly"), option-a was implemented directly without re-prompting. This matches D-31/D-32's explicit wording (one canonical tri-state concept, not a permanent dual-field compatibility layer) and the recommended option in the checkpoint's own text.
- **missingCategoryIds/missingCategoryNames scope narrowed to 'red' lines only.** A 'yellow' line has a substitution available (even if not the recipe's preferred ingredient), so its category is not "missing" in the sense the field name implies — only 'red' lines (nothing satisfies the line at all) contribute to these arrays. This matches the plan's explicit instruction.
- **Adjacency edge case resolves to red, not yellow.** When a locked-specific ingredient is out of stock AND is the only member of its category, there is no "other in-stock ingredient in the category" to offer as a substitute, so the line is red — tested explicitly in `makeableEngine.test.ts`.
