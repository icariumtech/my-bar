<objective>
Rebuild Barback's top-level navigation from header buttons that open stacked modals to a persistent bottom tab bar with exactly three tabs (Ingredients/Recipes/Settings), each with its own "Add {Item}" entry point in the upper-right (D-23/D-25). This plan establishes the architecture every later plan in this phase builds on: App.tsx becomes a thin shell holding only which tab is active, while each tab container owns its OWN local add/edit/detail view state — so later plans that build out full-screen forms for a given entity only ever touch that entity's own tab file, never App.tsx again after this plan lands.

At this stage, tapping "Add Ingredient"/"Add Recipe"/"Categories"/"Glassware" still opens the EXISTING modal-based forms (AddEditIngredientForm, RecipeForm, RecipeDetailView, CategoryManager, GlasswareManager) — unchanged internally, just reached through the new tab-based UI instead of header buttons. Converting those modals to full-screen views (D-26) is later plans' scope; this plan's job is BARBACK-01 (the tab bar itself) end to end.

Purpose: BARBACK-01 replaces a navigation pattern that doesn't scale past 3-4 entry points (header buttons) with the persistent-tab pattern every mobile-first inventory app uses, and decentralizing view-state to each tab is what lets the remaining 5 plans in this phase run with minimal cross-plan file contention.

Output: `BottomTabBar` component; `App.tsx` reduced to a thin activeTab shell; `IngredientsTab`/`RecipesTab`/`SettingsTab` containers, each wrapping the existing list/management components with the new header + Add button pattern.
</objective>
