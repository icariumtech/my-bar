    Create `apps/barback/src/components/pickers/IngredientPicker.tsx`. This component does NOT rely on antd's automatic `Form.Item` value/onChange cloning (that clone pattern only carries a single scalar value; this field writes three related values at once) — it accepts and emits a composite value directly as plain props: `interface IngredientPickerValue { categoryId: string | undefined; ingredientId: string | null; requiresSpecific: boolean }` and `interface IngredientPickerProps { value: IngredientPickerValue; onChange: (next: IngredientPickerValue) => void }`. The later plan that wires this into the recipe ingredient-line form is responsible for reading/writing the row's three underlying `Form.List` fields via a `<Form.Item noStyle shouldUpdate>` render-prop around this component — note that wiring responsibility here, but do not implement it in this file.

    Internally call `useCategories()` and `useIngredients()` (both already exist, unchanged). Use antd `AutoComplete` with grouped options: `[{ label: 'Categories', options: categories.map(c => ({ value: \`cat:${c.id}\`, label: c.name })) }, { label: 'Ingredients', options: ingredients.map(i => ({ value: \`ing:${i.id}\`, label: \`${i.name} (${i.categoryName})\` })) }]` — the `cat:`/`ing:` value prefix is how `onSelect` distinguishes which namespace was picked (RESEARCH.md Pitfall 2: label format must let the owner tell a category apart from a specific bottle at a glance). On selecting a `cat:` option: `onChange({ categoryId: <id>, ingredientId: null, requiresSpecific: false })`. On selecting an `ing:` option: `onChange({ categoryId: <that ingredient's categoryId>, ingredientId: <id>, requiresSpecific: true })` (D-30: default checked).

    When `value.ingredientId` is non-null, render a `<Checkbox checked={value.requiresSpecific} onChange={(e) => onChange({ ...value, requiresSpecific: e.target.checked })}>Must be this specific ingredient</Checkbox>` directly below the `AutoComplete`. Render nothing extra when `value.ingredientId` is null (plain category line — no checkbox at all, per the must_haves truth).

    Display value: if `value.ingredientId` is set, show that ingredient's name; else if `value.categoryId` is set, show that category's name; else empty string.

    For the "+ Add new ingredient" trigger: append it to the option list only when the trimmed search text is non-empty AND does not case-insensitively match any existing ingredient name (`ingredients.some(i => i.name.toLowerCase() === trimmed.toLowerCase())`) — this exact check is what this plan's first prohibition requires. For this task, selecting "+ Add new ingredient" should call a `onRequestCreate?: (name: string) => void` prop (optional, wired by task 2) rather than implementing the creation sub-flow inline — task 2 adds the real inline sub-form and passes this callback.
