## Initial vision dump

User described the target state freeform before any structured questions: remove "My Bar — Barback" header title; bottom tab bar (Ingredients/Recipes/Categories, later clarified to Settings); "Add {Item}" button upper-right per tab; undecided where Glassware/Categories management lives (settled on Settings tab); recipe edit goes full-screen with back navigation; autocomplete-with-inline-add-new for ingredient categories, and the same pattern wanted for ingredients+glassware inside recipes; recipe ingredients should allow a category OR a specific ingredient.

| Option | Description | Selected |

**User's choice / notes:** Neither option as originally framed — user specified a richer tri-state design instead: "I want a simple indicator, green if everything is good, yellow if ingredient is specified but missing but we still have another one in the same category, red if missing both... maybe we also need a checkbox on each ingredient to say if category is ok or if it has to be specific." ## Default checkbox state

| Option | Description | Selected |
|--------|-------------|----------|
| Category OK by default | Matches today's behavior; opt into "must be specific" | |
| Must be specific by default | Opt into category-substitutable | ✓ |

**User's choice:** Must be specific by default. **Rationale (verbatim):** "in most cases the booze is going to be a category and mixers are specific so a category checked as specific doesn't really do anything" — i.e. booze lines are naturally selected at the category level (so the checkbox is moot for them), while lines where a specific ingredient is deliberately picked are usually the non-substitutable mixer case, so defaulting to locked matches the common case without adding friction to booze entry.
