## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px | 400 | 1.5 | Recipe descriptions, ingredient lists, body copy in detail view |
| Label | 12px | 400 | 1.4 | Tag labels, secondary text, ingredient quantity units |
| Heading | 20px | 600 | 1.2 | Drink card titles, detail screen drink name, rail group titles |
| Display | 28px | 600 | 1.2 | Full-screen detail view main title (rarely used, reserved for prominent headers) |

**Notes:**
- Exactly two weights: 400 (regular) and 600 (semibold). No italic, no 300/700 variants.
- Matches Barback's pattern (D-13, 01-UI-SPEC.md) for consistency across screens
- No custom webfont; system fonts render instantly on iPad/phone Safari
- Line height 1.5 for body ensures readability at 16px on tablets; 1.4 for labels fits tag density; 1.2 for headings keeps them tight

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #1a2332 | Page background, main content area background |
| Secondary (30%) | #2d3f52 | Card containers, rail background, detail view content box |
| Accent (10%) | #ff6b35 | Rail group icons, tag pill backgrounds, primary action indicators, neon border accents |
| Success | #10b981 | Makeable-badge fill (when drink is makeable; green interior on card/detail) |
| Accent Text | #4dd0e1 | Secondary ingredient text, descriptive metadata (origin/decade), emphasis within descriptions |
| Destructive | #ef4444 | Not-makeable badge, error states, alert indicators |
| Text Primary | #ffffff | All primary text (drink names, body copy, ingredient lists) |
| Text Secondary | #b0b0b0 | Dimmed/secondary text (e.g., muted tag names, helper text) |

**Accent reserved for:**
- Rail group icons (Spirit, Type, Season, Flavor) and their submenu labels
- Tag pill backgrounds (multi-value tags shown on card and detail)
- Primary interactive elements (if any buttons exist in this phase; see PATR-06's browse-only scope)
- Neon border accents on card and detail container frames

**Success reserved for:**
- Makeable-badge fill (when drink is makeable; green interior on card/detail)
- Makeable status indicators (small-footprint success/availability color, not part of the 60/30/10 dominant/secondary/accent split)

**Destructive reserved for:**
- Not-makeable badge fill (red interior on card/detail when drink cannot be made)
- Error state backgrounds and text
- Alert/warning indicators
- No destructive actions in Phase 3 (ordering and deletion are Phase 4)

**Rationale:**
- Dark navy (#1a2332) and slate (#2d3f52) create the low-light bar aesthetic from reference photos, suitable for wall-mounted iPad
- Orange (#ff6b35) matches the neon glow visible in reference photos and provides high contrast against dark backgrounds for accessibility
- Cyan (#4dd0e1) adds visual interest for secondary content (origin stories, ingredient notes) without competing with orange
- Red (#ef4444) is universally understood for "unavailable/error"; pairs with Barback's destructive token (02-UI-SPEC.md, D-12) for consistency

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | N/A — this phase is browse-only (PATR-06); no explicit "Order" button exists until Phase 4 |
| Empty state heading | No drinks available |
| Empty state body | No recipes match this filter. Try browsing another category. |
| Error state heading | Something went wrong |
| Error state body | Failed to load drinks. Please check your connection and try again. |
| Not-makeable indicator (card badge) | Not Available |
| Not-makeable indicator (detail view) | Not Available — [ingredient names] missing |
| Makeable indicator (card badge) | Available |
| Makeable indicator (detail view) | Available |

**Notes:**
- "Not Available" for patrons is clearer than "Yellow" or "Substitution Available" (MATCH-05 tri-state concept); substitution judgment belongs to the bartender (D-42)
- Missing ingredients shown on detail only, not on card (D-44), so the detail-view line appears only on detail screens
- Browse-only this phase (PATR-06, PATR-05 deferred to Phase 4); no order submission copy or confirmation dialogs needed
- No destructive actions in Phase 3

## UI Considerations

Applicable state considerations resolved: **7 covered, 1 backstop**

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| Empty | Drink list (filtered/all) | ✅ covered | When no recipes match the current tag filter or category rail selection, "No drinks available" copy renders; patron can tap another category to re-populate |
| Loading | Drink list, drink detail | ✅ covered | API calls populate via TanStack Query; loading states render a skeleton card row or spinner (visual TBD in planning phase) until data arrives or error occurs |
| Error | API failure (list or detail fetch) | ✅ covered | "Something went wrong" copy with retry prompt; error state does NOT crash the app or leave UI blank |
| Populated | Drink list | ✅ covered | Cards render in a grid with name/tags/makeable-badge per D-38; detail view renders name/tags/ingredients/description/badge per D-39 |
| Partial | Missing description on detail | ✅ covered | Description field is optional (added in D-40); detail view only renders the description box if non-empty (explicit check in component) |
| Overflow | Description text | 🧪 backstop | If description text exceeds container height, scrolling is enabled within the detail view's content area (visual treatment TBD in planning phase — may be a scrollable div or modal/bottom-sheet) |
| Long text | Drink name, ingredient list | ✅ covered | Long drink names wrap to multiple lines; ingredient lists grow vertically without breaking layout |
| Zero-one-many | Ingredient list per drink | ✅ covered | Recipes always have ≥1 ingredient (enforced by data model); no special "no ingredients" state needed |

## Edge Cases & Special Behavior

**Live Sync (D-46, D-47):**
- When a drink's makeable status changes live (Barback inventory update → Socket.IO push → TanStack Query refetch):
  - Card badge updates silently in-place (no pulse/flash animation this phase)
  - Detail screen updates live if patron has it open
  - Both surfaces subscribe to the same makeable state; single source of truth via `computeMakeable()` on backend

**Tag Rail Filtering (D-36):**
- A rail group's submenu only shows tags that currently have ≥1 recipe tagged (computed live, not hardcoded)
- Tapping a tag applies it as a single active filter (replaces previous filter, single-filter-at-a-time model — D-37)
- Patron can tap the group icon again or swipe/navigate to browse other categories without multi-select

**Makeable Status Collapse (D-42):**
- Barback's tri-state (green/exact-match / yellow/substitution-available / red/missing) is read from `computeMakeable()` API response
- Patron collapses yellow → "Not Available" (substitution judgment belongs to bartender, not patron)
- Display layer only; does NOT change backend computation

**Not-Makeable Visual (D-43):**
- Cards with not-makeable status are dimmed/desaturated (opacity ~0.6 or grayscale filter)
- Badge still visible and clear on dimmed card
- Patron can tap dimmed card to see missing ingredients detail
- Not-makeable drinks remain fully visible and tappable (no hide/filter toggle; satisfies PATR-06)

**Visual Hierarchy & Focal Point (Browse Grid):**
- Drink name (20px, weight 600, #ffffff) is the primary visual focal point on each card
  - Top-left or top-center position, maximum contrast text
  - Draws the eye first before tags, badge, or secondary details
  - Supports rapid browsing: patron scans card names to find a drink of interest, then reads tags/ingredient list on detail view

## Implementation Notes

**Patron App Structure (new `apps/patron`):**
- Separate workspace package from Barback (per monorepo pattern in CLAUDE.md)
- Vite SPA build with React 19 + TypeScript
- Tailwind v4 via `@tailwindcss/vite` plugin (no postcss.config, no tailwind.config.js needed)
- TanStack Query hooks for API state (fetch drink list, fetch detail, subscribe to live updates)
- Socket.IO client listener for makeable status pushes

**API Integration:**
- GET `/api/recipes` — fetch all recipes with tags, current makeable status, counts per tag-group (for D-36 empty-tag hiding)
- GET `/api/recipes/:id` — fetch single recipe detail with description and full ingredient list
- Socket.IO `recipe:updated` event triggers TanStack Query invalidation of `['recipes']` cache

**Icons (Lucide):**
- Spirit group: `Wine2` (or `Bottle`), Type group: `Sparkles` (or `Star`), Season group: `Leaf`, Flavor group: `Flame`
- Specific tag icons TBD in planning phase (e.g., Whiskey → `Flame`, Gin → `Leaf`, etc.)
- Back button on detail: `ChevronLeft` (circular container, Success color #10b981 — matches FullScreenHeader pattern from 260812-m0i)

**Placeholder Photo Treatment (D-41):**
- Detail view hero slot shows a centered cocktail glass silhouette or solid gradient block (TBD in planning phase)
- Placeholder is NOT clickable; it's purely visual spacing
- Makeable badge positioned in the "price slot" (bottom-right of card, separately from photo)
