<objective>
Close PATR-07 and PATR-08: the Patron app requests fullscreen and a screen wake-lock once on load (graceful no-op on any browser that denies or lacks either), and returns to the browse grid after 90 seconds of zero touch/mouse/key activity — turning the wall-mounted iPad into a real unattended kiosk rather than a browser tab someone has to babysit.

This plan is fully independent of Plan 04-01's order-submission/Bartender work — different files, zero dependency — and runs in the same wave for maximum parallelism.

Purpose: an unauthenticated, wall-mounted, guest-facing screen with no session/lock-out mechanism will otherwise sit wherever the last person left it (deep in a detail view, browser chrome visible with a URL bar) — a kiosk that never resets undermines the entire "no login friction for guests" design (`.claude/CLAUDE.md`'s Access Model constraint) by making every next guest inherit the prior guest's navigation state.
Output: `useKioskInactivity`/`useFullscreen`/`useWakeLock` hooks, unit-tested against fake timers and mocked browser APIs; wired into `App.tsx` (fullscreen + wake-lock) and `RecipeBrowse.tsx` (inactivity → return to grid).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser Fullscreen/Wake-Lock APIs → Patron app | Client-only browser capability requests; no server round-trip, no new network-facing surface |
| Inactivity timeout → in-app navigation state | Purely local state reset (`viewingId`); no data is deleted or mutated |

| T-04-15 | Denial of Service | A rejected/unsupported Fullscreen or Wake-Lock API call | low | mitigate | Both hooks wrap the browser call in try/catch (fullscreen) or `.catch()` (wake-lock) so a rejection degrades gracefully — the app never crashes or becomes unusable because a browser capability was denied |
| T-04-16 | Information Disclosure | Kiosk returning to the browse/home view after inactivity | low | accept | This is the INTENDED mitigation for the real risk (a guest's in-progress detail-view navigation or an open order prompt being left visible for the next person) — accepted as the correct behavior, not a residual threat to further mitigate |
