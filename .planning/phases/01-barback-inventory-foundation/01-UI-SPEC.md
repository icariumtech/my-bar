## Design System

| Property | Value |
|----------|-------|
| Tool | Ant Design (antd) — explicit user decision, see Deviation note below |
| Preset | not applicable (Ant Design has no shadcn-style preset/registry model) |
| Component library | Ant Design (antd) v5.x — exact patch version to be pinned by the planner via a live npm registry check (component-library choice was made after 01-RESEARCH.md was finalized, so it carries no registry/legitimacy audit yet) |
| Icon library | `@ant-design/icons` (Ant Design's official icon set) |
| Font | Ant Design v5 default font stack: `-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif, 'Apple Color Emoji', 'Segoe UI Emoji', 'Segoe UI Symbol'` — used as-is, no custom webfont, consistent with D-13's utilitarian/minimal-chrome mandate |

> **Deviation from `.claude/CLAUDE.md` stack doc (assumption / open note for planner and future phases):**
> `.claude/CLAUDE.md`'s Recommended Stack specifies **Tailwind CSS with no named component library** (hand-rolled components, chosen specifically so nothing fights the dark-neon Patron aesthetic). Per explicit user decision made during this UI research session, **Ant Design (antd) is now the selected component library for the Barback screen** (Add/Edit Ingredient form, Category management, buttons, inputs, alerts, spinners). Tailwind remains available alongside Ant Design for custom layout/utility styling (e.g. the custom swipe-row visuals, which are not an Ant Design component). This pivot has **not** been written back into `.claude/CLAUDE.md` — the planner should either (a) treat this UI-SPEC as the authoritative override for Phase 1's frontend dependency list, adding `antd` + `@ant-design/icons` to `apps/barback`'s install list in place of/alongside the Tailwind-only plan in 01-RESEARCH.md, or (b) flag back to the user if they want CLAUDE.md itself updated. This choice is scoped to Barback only — whether Ant Design also applies to the Patron (dark-neon, guest-facing) and Bartender screens in later phases is an open question for those phases' own UI research, not decided here.

### Ant Design Theme Configuration (implementation-ready mapping)

Dark theme via Ant Design v5's `ConfigProvider`, using `theme.darkAlgorithm` as the base with token overrides mapped to the Color contract below — this is the concrete wiring the executor should use, not a fresh design decision:

| Ant Design token | Value | Maps to |
|---|---|---|
| `colorBgLayout` | `#18181b` | Dominant (60%) |
| `colorBgContainer` | `#27272a` | Secondary (30%) — cards, rows, form surfaces |
| `colorPrimary` | `#22c55e` | Accent (10%) |
| `colorError` | `#ef4444` | Destructive |

```tsx
<ConfigProvider theme={{ algorithm: theme.darkAlgorithm, token: {
  colorBgLayout: '#18181b', colorBgContainer: '#27272a',
  colorPrimary: '#22c55e', colorError: '#ef4444',
}}}>
```

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: **48px minimum tap target** for swipe-toggle ingredient rows, the "Add Ingredient" / "Add Category" buttons, and the Undo affordance — per D-13's "large tap targets and minimal chrome... optimized for one-handed thumb use."

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#18181b` (zinc-900) | Page background, layout surface |
| Secondary (30%) | `#27272a` (zinc-800) | Ingredient rows, cards, form surfaces, nav |
| Accent (10%) | `#22c55e` (green) | In-stock status indicator, primary CTA buttons ("Add Ingredient", "Add Category", "Save"), active/selected filter chip |
| Destructive | `#ef4444` (red) | Out-of-stock swipe-reveal background, category-delete-blocked error, destructive confirmations |

Accent reserved for: **primary CTA buttons only** ("Add Ingredient", "Add Category", "Save"/"Save Changes"), the **in-stock status indicator** (dot/badge on each row), and the **active/selected state of the search/filter control**. Never used for body text, non-primary buttons, or decorative elements.

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 8 covered, 5 backstop, 1 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | IngredientList (list-collection) | ✅ covered | True-empty state (zero ingredients ever added) renders "No ingredients yet" / "Add your first bottle to start tracking inventory." per Copywriting Contract |
| empty | SearchFilterBar + IngredientList, filtered (form + list-collection) | 🧪 backstop | Filtered-zero-results state renders distinct copy "No matches for '{query}'" — not part of the user-approved Copywriting Contract, asserted here as a default; must not be confused visually with the true-empty state row above |
| loading | IngredientList (list-collection) | 🧪 backstop | List fetch shows an Ant Design `<Spin/>` + "Loading inventory…" label before the first successful `GET /api/ingredients` response resolves |
| error | IngredientList (list-collection) | 🧪 backstop | List fetch failure shows an inline Ant Design `<Alert type="error">` reading "Couldn't load inventory — check your connection and try again." with a Retry action |
| populated | IngredientList (list-collection) | ✅ covered | Normal populated state renders IngredientRow items in a vertical scrolling list, secondary-surface rows (`#27272a`) on dominant background (`#18181b`) |
| zero-one-many | IngredientList (list-collection) | ✅ covered | Zero → empty-state row above; One → single row renders identically to many, no singular/plural count label needed; Many (up to ~50-100 per 01-RESEARCH.md scale estimate) → standard vertical scroll, no pagination |
| overflow | IngredientList (list-collection) | ✅ covered | Overflow handled by native vertical scroll; no virtualization needed at this row-count scale |
| partial | AddEditIngredientForm (form) | ✅ covered | Name and Category are required (Ant Design Form validation, D-01/D-05); Note is optional with no partial-state UI beyond a blank field (D-06) |
| error | AddEditIngredientForm (form) | ✅ covered | Submit failure shows the Copywriting Contract's Error state copy via Ant Design Form `validateStatus`/`help`, or a form-level `<Alert>` for network failures |
| loading | AddEditIngredientForm (form) | ✅ covered | Submit-in-flight disables the Save button and shows Ant Design Button's built-in `loading` spinner state |
| long-text | AddEditIngredientForm (form) | ✅ covered | Name field enforces the Zod `max(200)` constraint via `maxLength` on the Input; no character counter shown (utilitarian, minimal chrome per D-13) |
| long-text | IngredientRow (interactive-control) | 🧪 backstop | Ingredient name overflow in a row truncates to one line with CSS ellipsis; full name remains visible when the row opens into the edit form |
| error | IngredientRow swipe-toggle (interactive-control) | 🧪 backstop | If the deferred `PATCH` (01-RESEARCH.md Pattern 2) fails after the undo grace period elapses, the row optimistically reverts to its prior in/out-of-stock state and a toast reads "Couldn't update stock — try again." |
| empty | CategoryManager (list-collection + form) | ⚠ unresolved | No copy defined for the zero-categories-exist state (owner hasn't created any category yet, which blocks ingredient creation since Category is required per D-01/D-02) — planner should treat as an assumption and confirm handling (e.g. inline prompt to create a first category) with the owner during UAT |
