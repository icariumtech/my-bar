<objective>
Close UAT gap G-02-6: recipe creation/edit is 100% broken because `UnitDropdown` and `GlasswareSelector` are prop-less wrappers that never forward the `value`/`onChange` antd's `Form.Item` injects, so every submitted ingredient line's `unit` is `undefined`, which fails the shared Zod contract's required `z.enum(...)` and 400s on every save. `apiFetch` also discards the server's real `{error}` body, which is why the failure reads as a generic "check your connection" message instead of a validation error. Root cause already diagnosed in `.planning/debug/recipe-save-fails-connection.md` — this plan only fixes it and adds the regression guard that should have caught it.

Purpose: RECIPE-01 (create) and RECIPE-02 (edit) are both unusable end-to-end until this is fixed — this is the single blocker keeping Phase 2's UAT from proceeding past test 6.

Output: working recipe create/edit through the real Barback UI, a real (not generic) save-failure message, and a vitest+RTL regression test that fails on the old broken components and passes on the fixed ones.
</objective>
