<objective>
Close UAT gap G-02-9: after toggling an ingredient's in-stock status via the Barback swipe-to-toggle action, the Recipes list/detail's makeable badge stays stale until a manual page reload. Root cause already diagnosed in `.planning/debug/stale-makeable-badge.md` — `useToggleStock` in `apps/barback/src/api/useIngredients.ts` invalidates only the `['ingredients']` query key in `onSettled`, never `['recipes']`, even though every recipe's `makeable`/`missingCategoryNames` fields are derived from live ingredient stock (the server recomputes correctly on every request; this is purely a missing client cache invalidation). `useUpdateIngredient` has the same latent gap. This plan only fixes it and adds the regression guard that should have caught it.

Purpose: MATCH-01's "single source of truth, server-side" guarantee is only trustworthy if every screen's client cache actually resyncs when the underlying inventory changes — this plan closes the one mutation path that was skipping that resync.

Output: `useToggleStock` and `useUpdateIngredient` both invalidate `['recipes']` in `onSettled`, matching the codebase's own established cross-entity-invalidation pattern (`useUpdateGlassware`, `useRenameCategory`), plus a vitest regression test that fails on the old code and passes on the fixed code.
</objective>
