# Phase 2.1 Plan 04: Category/Glassware Manager Full-Screen Conversion Summary

**Converted Barback's Settings-tab Categories and Glassware sub-pages from Modal-wrapped to full-screen views with a back button (D-24/D-26), with zero change to their existing inline add/rename/delete logic.**

## Performance

- **Duration:** ~15 min
- **Completed:** 2026-08-12
- **Tasks:** 2
- **Files modified:** 5 (2 components converted, 2 new test files, 1 container rewired)

## Accomplishments

- `CategoryManager.tsx` converted from `{ open, onClose }` Modal props to `{ onBack }` full-screen props; Modal wrapper replaced with the flex-column shell (header with back button + `<main>`) established in `02.1-PATTERNS.md`
- `GlasswareManager.tsx` converted identically, mirroring `CategoryManager.tsx`'s exact shell pattern
- `SettingsTab.tsx` now early-returns the active sub-page full-screen (menu is never rendered underneath) instead of always mounting both managers behind `open`/`onClose`
- Two new test files (`CategoryManager.test.tsx`, `GlasswareManager.test.tsx`) covering: no `role="dialog"` present, back button wired to `onBack`, and existing list/add affordances still render
- All internal add/rename/delete mutation logic (`useCategories`/`useCreateCategory`/`useRenameCategory`/`useDeleteCategory` and the glassware equivalents) is untouched — verified by diff review, byte-for-byte unchanged function bodies

## Decisions Made

- `SettingsTab` uses early `if (view === 'categories') return <CategoryManager onBack={...} />` (and the glassware equivalent) rather than conditional JSX inside the menu's returned tree — cleanest way to guarantee the menu is never rendered underneath the active full-screen sub-page, matching `IngredientsTab`'s established pattern from plan 02.1-02.
