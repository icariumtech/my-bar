## Color

Inherited from Phase 1/2 (60/30/10 color split) — **EXTENDED** with warning tone:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#18181b` (zinc-900) | Page background, bottom tab bar background, full-screen view backgrounds |
| Secondary (30%) | `#27272a` (zinc-800) | Tab content surfaces, form backgrounds, ingredient/recipe rows |
| Accent (10%) | `#22c55e` (green) | Ready-to-make badge (green state), primary CTA buttons, active tab indicator |
| Warning (NEW) | `#facc15` (yellow) | Substitution-available badge (yellow state), warning-level UI alerts |
| Destructive | `#ef4444` (red) | Missing-ingredients badge (red state), delete confirmations, error messages |

### Accent Reserved For (Phase 2.1 Additions)

Accent (`#22c55e`) is reserved **exclusively** for:
- **Makeable status badge (green)** on recipe rows and detail (✓ Ready to make)
- **Primary CTA buttons** ("Add Recipe", "Save Recipe", "Add Category", "Add Glassware", when in create mode)
- **Active tab indicator** on bottom tab bar (Ingredients / Recipes / Settings — whichever is active)
- **"Add {Item}" buttons** in upper-right of Ingredients/Recipes tabs

Never used for body text, secondary navigation buttons, form hints, or decorative elements.

### Warning Reserved For (NEW)

Warning (`#facc15`) is reserved **exclusively** for:
- **Makeable status badge (yellow)** on recipe rows and detail (⚠ Substitution needed — locked ingredient out of stock, but alternative available)
- **Warning-level alerts** on recipe forms (e.g., "This ingredient is no longer in stock")

Never used for secondary UI, general text, or non-critical information.

### Destructive Reserved For

Destructive (`#ef4444`) is reserved **exclusively** for:
- **Makeable status badge (red)** on recipe rows and detail (✗ Missing ingredients)
- **Delete confirmations and irreversible action warnings**
- **Error messages and validation failures**

### Focal Points (Phase 2.1)

The **bottom tab bar** (Ingredients / Recipes / Settings) is the primary navigation focal point. Within each tab, the **"Add {Item}" button** (upper right, accent color, 48px min height) is the secondary focal point. For tri-state badges on recipes, the **tri-state status indicator** (green/yellow/red) is a key focal point guiding user decisions about makeable/substitution/missing scenarios.

## Component Inventory (Phase 2.1 Additions to Phase 1/2)

### Navigation & Tab Bar (NEW — D-23/D-24/D-25)

- **BottomTabBar**: Persistent tab navigation at bottom of viewport. Uses antd `Segmented` component styled to bottom (sticky positioning) with exactly 3 tabs: Ingredients, Recipes, Settings. Active tab highlighted with accent color. Clicking a tab switches `activeTab` state and re-renders tab content pane below.
  - Tabs: [Ingredients] [Recipes] [Settings]
  - Active tab: left-to-right order; defaults to "Ingredients"
  - Style: sticky bottom, 48px min-height, flex layout with equal-width tabs

- **IngredientsTab**: Container for ingredients list view. Header with "Ingredients" label + "Add Ingredient" button (upper right, accent color, 48px min height). Body renders IngredientList component (inherited from Phase 1).

- **RecipesTab**: Container for recipes list view. Header with "Recipes" label + "Add Recipe" button (upper right, accent color, 48px min height). Body renders RecipeList component with tri-state badges (extended from Phase 2).

- **SettingsTab**: Settings navigation menu. Renders a flat list/menu with two navigation items:
  1. "Categories" — link/button opens full-screen AddEditCategoryView
  2. "Glassware" — link/button opens full-screen AddEditGlasswareView
  - Menu style: secondary-surface list items (`#27272a` background), list-standard text styling (Heading role)

### Full-Screen Views (NEW — D-26)

All add/edit/detail flows now open as full-screen views instead of modals. Each view has a header with a back button (left-aligned, no icon text) that navigates back to the parent list/tab.

- **AddEditIngredientView**: Full-screen form for adding or editing an ingredient.
  - Header: Back button + "Add Ingredient" (if adding) or "Edit Ingredient" (if editing)
  - Body: Name field + CategoryPicker (AutoComplete, D-27) + stock status toggle
  - Footer: Submit button ("Save Ingredient"), Cancel/Back link

- **AddEditRecipeView**: Full-screen form for adding or editing a recipe (extended from Phase 2).
  - Header: Back button + "Add Recipe" (if adding) or "Edit Recipe" (if editing)
  - Body: Name field + IngredientPicker (AutoComplete, D-28/D-29) with specific-lock checkbox + Method steps editor + GlasswarePicker (AutoComplete, D-27) + Garnish field
  - Footer: Submit button ("Save Recipe"), Cancel/Back link

- **AddEditCategoryView**: Full-screen form for adding or editing a category (refactored from Phase 2's modal).
  - Header: Back button + "Add Category" or "Edit Category"
  - Body: Name field (required, max 200)
  - Footer: Submit button ("Save Category"), Cancel/Back link

- **AddEditGlasswareView**: Full-screen form for adding or editing glassware (refactored from Phase 2's modal).
  - Header: Back button + "Add Glassware" or "Edit Glassware"
  - Body: Name field (required, max 200)
  - Footer: Submit button ("Save Glassware"), Cancel/Back link

- **RecipeDetailView**: Full-screen recipe detail view (refactored from Phase 2's modal).
  - Header: Back button + recipe name (Display role typography)
  - Body: Ingredients list (with per-line tri-state status, D-31) + Method steps + Glassware + Garnish
  - Prominent tri-state badge showing recipe-level status (D-32) with color-coded icon and text
  - Footer: Edit/Delete affordances

### AutoComplete Pickers (NEW — D-27/D-28/D-29)

Replace static `<Select>` dropdowns with unified autocomplete-with-inline-create pattern:

- **CategoryPicker**: AutoComplete field for selecting or creating an ingredient category.
  - Displays: existing categories as options
  - Search: filters categories by name (case-insensitive)
  - "+ Add new" option: shown when search text matches no existing entry; selecting it creates new category inline and updates form value (D-29)
  - Uses antd AutoComplete component with custom option rendering

- **IngredientPicker**: AutoComplete field for selecting or creating a recipe ingredient (D-28).
  - Displays: existing categories + existing ingredients in one option list
  - Search: filters both categories and ingredients by name
  - Categories: selectable, behave like today's category-only matching (D-28)
  - Ingredients: selectable, trigger display of "Must be this specific ingredient" checkbox (D-30, default checked)
  - "+ Add new" option: creates new ingredient inline (name + category + stock status) without leaving the recipe form (D-29)
  - Visual distinction: render categories and ingredients with different formatting (e.g., "Rum (category)" vs. "Havana Club (Rum, specific ingredient)")

- **GlasswarePicker**: AutoComplete field for selecting or creating glassware (D-27).
  - Displays: existing glassware types as options
  - Search: filters glassware by name
  - "+ Add new" option: creates new glassware inline and updates form value

### Tri-State Makeable Status (NEW — D-31/D-32)

- **MakeableStatusBadge** (extended from Phase 2): Displays recipe-level makeable status with tri-state support.
  - Green state: `<Tag icon={<CheckCircleOutlined />} color="success">Ready to make</Tag>` (accent color #22c55e)
  - Yellow state: `<Tag icon={<WarningOutlined />} color="warning">Substitution needed</Tag>` (warning color #facc15)
  - Red state: `<Tag icon={<CloseCircleOutlined />} color="error">Missing ingredients</Tag>` (destructive color #ef4444)
  - Accepts tri-state enum prop (Green | Yellow | Red) instead of boolean

- **IngredientStatusIndicator** (NEW): Per-line indicator on RecipeDetailView ingredient lines (D-31).
  - Each ingredient line displays a small icon/color showing line-level tri-state status (green dot / yellow dot / red dot)
  - Hover/tap reveals full status text ("In stock" / "Substitution available" / "Out of stock")

- **IngredientLockCheckbox** (NEW): "Must be this specific ingredient" checkbox on recipe ingredient lines (D-30).
  - Appears only when ingredient line has a specific ingredient selected (not a plain category)
  - Defaults to checked=true (D-30 requirement)
  - Label: "Must be this specific ingredient" or "Locked to [ingredient name]"
  - Unchecking converts line to category-only matching (ingredient selection is kept for display, but `requiresSpecific` flag becomes false)

## Interaction Patterns (Phase 2.1)

### Navigation Workflow

1. **Bottom Tab Bar**: User taps a tab (Ingredients / Recipes / Settings)
   - Tab becomes active (highlighted with accent color)
   - View pane switches to show that tab's content (IngredientList / RecipeList / SettingsMenu)
   - Header updates to show tab-appropriate "Add {Item}" button (or Settings menu)

2. **Add {Item} Workflow**: User taps "Add Ingredient" / "Add Recipe" / etc.
   - Full-screen AddEditIngredientView / AddEditRecipeView / etc. opens
   - Header shows back button + form title
   - User enters data and clicks "Save"
   - Form submits; on success, full-screen view closes and list updates
   - Clicking back navigates back to list without saving

3. **Edit {Item} Workflow**: User taps edit affordance on a list row
   - Full-screen AddEditIngredientView / AddEditRecipeView / etc. opens with pre-filled data
   - Back button returns to list without saving
   - Submit saves changes and closes view

4. **View Recipe Detail**: User taps a recipe row
   - Full-screen RecipeDetailView opens showing all recipe details
   - Tri-state badge prominently displayed at top
   - Back button returns to recipes list

### AutoComplete Picker Workflow (D-27/D-28/D-29)

1. **Select Existing Entry**: User clicks/taps AutoComplete field, types to search existing categories/ingredients/glassware
   - Options filter as user types (case-insensitive)
   - User clicks desired option; form field updates with selection
   - Line resolves to existing entry (category, specific ingredient, or glassware)

2. **Create New Entry Inline**: User types in AutoComplete, text matches no existing entry
   - "+ Add new: [text]" option appears
   - User clicks it
   - New entry is created (via mutation) and form field updates immediately (optimistic update)
   - New entry is now available in future picker uses (persisted to database)

3. **Specific Ingredient Selection** (D-28): User selects a specific ingredient in recipe ingredient picker
   - "Must be this specific ingredient" checkbox appears, defaulting to checked (D-30)
   - User can uncheck it to convert to category-only matching
   - Checked state is persisted with recipe

4. **Inline Create Specific Ingredient** (D-29): User clicks "+ Add new" in recipe ingredient picker
   - Quick-create form appears (name + category selector + stock toggle)
   - After creation, ingredient is immediately selectable and pre-selected in the current form field
   - Checkbox state defaults to checked (D-30)

### Tri-State Makeable Status Workflow (D-31/D-32)

1. **View Recipe List**: Each recipe row displays tri-state badge
   - Green: "Ready to make" (accent color) — all ingredients satisfied
   - Yellow: "Substitution needed" (warning color) — at least one locked ingredient out of stock but substitute available
   - Red: "Missing ingredients" (destructive color) — at least one line unsatisfied

2. **View Recipe Detail**: Full-screen RecipeDetailView shows
   - Prominent recipe-level tri-state badge at top
   - Per-line ingredient status indicators (D-31): green dot / yellow dot / red dot on each ingredient line
   - Yellow/red lines show expanded hint text:
     - Yellow: "[ingredient name] is out of stock, but [alternative name] is available"
     - Red: "[ingredient name] is out of stock (no alternatives available)"

3. **Recipe Stock Changes**: When an ingredient's stock status changes (via Ingredients tab or Barback inventory update)
   - Recipes list automatically refreshes (via TanStack Query invalidation)
   - Recipe-level badge updates to reflect new tri-state
   - Detail view (if open) also updates
