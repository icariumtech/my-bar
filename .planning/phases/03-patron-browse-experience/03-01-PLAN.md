## Planner Assumptions (spec-less probe fallback, phase-wide)

No plain `03-SPEC.md` exists for this phase, so `03-UI-SPEC.md`'s own `## UI Considerations` table and a deterministic edge-probe run (see planning context) are the source for edge coverage instead of a SPEC's `## Edge Coverage`/`## Prohibitions` sections. Every probe item was resolved (never silently dropped) and threaded into `must_haves` on the plan that implements it:

- PATR-01 (unclassified → resolved explicit, this plan's App.tsx / 03-02's TagRail): zero-recipe / zero-active-tag states never crash, they render the UI-SPEC empty copy.
- PATR-02 (unclassified → resolved explicit, this plan + 03-04): a recipe with zero tags renders an empty tag row, not an error.
- PATR-03 adjacency (resolved explicit, this plan): yellow collapses identically to red — see must_haves above.
- PATR-03 empty (resolved backstop, this plan): MakeableIndicator has no defined behavior for a status outside the three enum values because `TriStateStatus` is a closed Zod enum enforced at the API boundary — recorded as a backstop truth rather than an executable test, since no code path can construct an invalid value.
- PATR-03 ordering (resolved explicit, 03-02): grid order is server-determined (name asc) and never reshuffled by makeable status.
- PATR-04 (unclassified → resolved explicit, 03-04): the missing-ingredients section renders only when `overallStatus === 'red' && missingCategoryNames.length > 0`, never a false-empty callout for a yellow-only not-available recipe.
- PATR-06 idempotency (resolved explicit, 03-02): repeated identical taps produce no duplicate side effects.
- PATR-06 concurrency (resolved explicit, 03-05): Patron is GET-only; concurrent Barback writes are surfaced exclusively via SYNC-01's live push.
- SYNC-01 (unclassified → resolved explicit, 03-05): Socket.IO reconnect explicitly re-syncs full state (Pitfall 4).

`03-UI-SPEC.md`'s "## UI Considerations" (7 covered + 1 backstop) is lifted identically: Empty/Loading/Error/Populated/Long-text land in this plan and 03-02; Partial/Overflow(backstop)/Zero-one-many land in 03-04.

Three prohibition-probe survivors (Stage 1 recall → Stage 2 precision, canon-security items dropped with a threat-model breadcrumb instead) are threaded into `must_haves.prohibitions` across the plan set: (1) no order/checkout CTA leaking into Patron ahead of Phase 4 scope (03-02), (2) no yellow-state/substitution wording leaking to the guest (this plan + 03-04), (3) live sync must never silently degrade to permanently-stale (03-05).

| T-03-03 | Tampering / Information Disclosure | `description` rendered on Patron/Barback | high | mitigate | React JSX text interpolation only, never `dangerouslySetInnerHTML` — canon XSS pattern, already covered by React's default escaping and the existing garnish/method plain-text-rendering precedent; not re-minted as a bespoke prohibition, breadcrumbed here instead |
| T-03-04 | Tampering / Elevation of Privilege | write-side `tags` shape | medium | mitigate | `recipeInput`/`recipePatch` accept only `tagIds` (uuid array), never a joined `tags` object array — Zod's object parsing does not merge extra client-sent keys into the insert, so a client cannot inject a fabricated tag name/group; the joined label is always server-derived from the `tags` table |
