# Quick Task 260812-jz9: Replace full-width "Add {Item}" button with an inline square "+" icon button

## Problem

Both `IngredientsTab.tsx` and `RecipesTab.tsx` currently render a separate
`<div className="flex justify-end pb-md">` row above their search bar,
containing a full-width-looking antd `Button` (`type="primary"`,
`icon={<PlusOutlined />}`, text "Add Ingredient"/"Add Recipe",
`style={{ minHeight: 48 }}`). The user wants that entire row removed and
replaced with a small square, icon-only "+" button placed directly beside
the search input, sized to match the input's rendered height exactly.

**Read-first discovery that changes the originally assumed approach:**
`IngredientsTab.tsx` renders `SearchFilterBar` (Input + category-chip row),
but `RecipesTab.tsx` does **not** use `SearchFilterBar` at all — it renders
its own bare antd `Input` with no chips (recipes have no category filter).
So:

- `SearchFilterBar.tsx` gets the new `onAdd`/`addLabel` props + square
  button (used only by `IngredientsTab`).
- `RecipesTab.tsx` gets the identical square-button-beside-Input pattern
  applied directly in its own JSX (not routed through `SearchFilterBar`,
  which would incorrectly pull in a category-chip row Recipes doesn't
  have).

**Height verification:** `SearchFilterBar`'s `Input` already carries
`size="large"` + `style={{ minHeight: 48 }}`, so its resolved rendered
height is 48px (the `minHeight` override wins regardless of antd's
`size="large"` default). `RecipesTab`'s bare `Input` currently has neither
`size` nor `style` set (default antd "middle" size, ~32px) — leaving it
unchanged would make the new 48px square button taller than its own row's
Input, failing both "match the search bar's height exactly" and creating a
visually mismatched row. Task 2 brings `RecipesTab`'s `Input` in line with
the same `size="large"` + `style={{ minHeight: 48 }}` pattern already
established on `SearchFilterBar`'s `Input`, so both rows resolve to the
same 48px height the button is sized to match.

## Fix

1. **`SearchFilterBar.tsx`**: add required `onAdd: () => void` and
   `addLabel: string` props. Restructure the component's first row from a
   lone `<Input>` into a `flex gap-sm items-center` row containing the
   `Input` (`className="flex-1"` so it keeps filling available width,
   otherwise unchanged) and a new square, icon-only `Button`
   (`type="primary"`, `icon={<PlusOutlined />}`, no text children,
   `aria-label={addLabel}` so it stays accessible and keeps an accessible
   name testable by role, `style={{ width: 48, height: 48, minWidth: 48,
   padding: 0 }}` so it renders as an actual square matching the Input's
   resolved 48px height rather than a pill/oval). The chip row stays below,
   unchanged. Add `SearchFilterBar.test.tsx` (no such file exists yet)
   covering the new button's render + click-calls-onAdd behavior.

2. **`IngredientsTab.tsx`**: remove the standalone
   `<div className="flex justify-end pb-md">...Add Ingredient Button...
   </div>` row entirely. Pass `onAdd={openAdd}` and
   `addLabel="Add Ingredient"` to `SearchFilterBar`. Drop the now-unused
   `Button`/`PlusOutlined` imports.

3. **`RecipesTab.tsx`**: remove the standalone "Add Recipe" button row the
   same way. Replace the lone `<Input>` with a `flex gap-sm items-center`
   row containing the `Input` (bumped to `size="large"` +
   `style={{ minHeight: 48 }}` + `className="flex-1"`, matching
   `SearchFilterBar`'s Input — see height-verification rationale above) and
   an identically-styled square `Button` (`aria-label="Add Recipe"`,
   `onClick={openAdd}`). `RecipesTab.test.tsx`'s existing
   `getByRole('button', { name: /Add Recipe/ })` queries keep working
   unmodified because `aria-label="Add Recipe"` is the button's computed
   accessible name even with no visible text — confirmed by reading both
   test files: neither currently asserts button *text*, and
   `IngredientsTab.test.tsx` has no Add-button assertion at all, so no test
   files need edits beyond the new `SearchFilterBar.test.tsx`.

Both tabs keep the existing 48px minimum touch-target convention and the
existing `type="primary"` accent-green (`#22c55e`) styling — no new color
is introduced.
