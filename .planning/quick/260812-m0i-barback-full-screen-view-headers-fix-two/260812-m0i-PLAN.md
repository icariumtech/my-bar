# Quick Task 260812-m0i: Fix the shared full-screen header pattern (centering + icon-only back button)

## Problem

Five Barback full-screen views —  `AddEditIngredientView.tsx`,
`AddEditRecipeView.tsx`, `RecipeDetailView.tsx`, `CategoryManager.tsx`,
`GlasswareManager.tsx` — each render an identical header block verbatim:

```tsx
<div style={{ display: 'flex', alignItems: 'center', gap: 8, padding: 16, borderBottom: '1px solid rgba(255,255,255,0.1)' }}>
  <Button type="text" onClick={onBack}>← Back</Button>
  <h2 className="text-white">{title}</h2>
</div>
```

(`RecipeDetailView`'s `<h2>` additionally carries `style={{ fontSize: 28,
fontWeight: 600 }}` — confirmed against `02.1-UI-SPEC.md`, which explicitly
documents RecipeDetailView's title as using **Display role typography**
(28px/600) versus the other 4 views' default `<h2>`, which resolves to the
global `h1,h2,h3 { font-size: 20px; font-weight: 600; }` rule in
`apps/barback/src/index.css` — i.e. **Heading role**. This is a real,
UI-SPEC-documented distinction, not an accident, so it must be preserved,
not unified away.)

**Two confirmed bugs in this shared markup:**

1. The title sits in a left-aligned flex row immediately after the Back
   button — it is not centered across the header's full width, it just
   starts wherever the button's rendered width happens to end.
2. "← Back" is a plain `type="text"` `Button` with an arrow character +
   the word "Back". The user wants a circular, icon-only back button using
   a real icon glyph, styled with the app's accent green — the same
   `type="primary"` treatment used for the square "+" Add buttons added in
   the immediately prior quick task (260812-jz9, `SearchFilterBar.tsx`).

**Fix approach:** extract a single reusable `FullScreenHeader` component
implementing the standard 3-column centering pattern (fixed-width left
button / flexible centered title / matching empty right spacer), with a
circular accent icon-only back button. All 5 views switch to it, removing
their duplicated inline markup. `RecipeDetailView` passes its distinct
28px/600 title style through an optional prop rather than losing it.

**Read-first discovery on test impact (all 5 `*.test.tsx` files read):**
Back-button selectors currently vary:

- `AddEditIngredientView.test.tsx` and `RecipeDetailView.test.tsx` both use
  `screen.getByRole('button', { name: /Back/ })` — a regex substring match.
  This still matches an icon-only button whose accessible name is
  `aria-label="Back"`. **No changes needed** to either file.
- `AddEditRecipeView.test.tsx` uses an **exact-string** match:
  `screen.getByRole('button', { name: '← Back' })`. This breaks once the
  visible text/arrow is gone — **must** be updated to `{ name: 'Back' }`.
- `CategoryManager.test.tsx` and `GlasswareManager.test.tsx` both query
  `screen.getByText('← Back')` (text content, not role/accessible name).
  This also breaks on an icon-only button with no matching text node —
  **must** be updated to `screen.getByRole('button', { name: 'Back' })`.

No assertion is weakened in any case — each updated query still proves
"clicking the back-navigation control calls `onBack`", just via the
button's accessible name instead of its now-removed visible text.

## Fix

1. **New `FullScreenHeader.tsx`** (`apps/barback/src/components/`, sibling
   to `MakeableStatusBadge.tsx`/`SearchFilterBar.tsx`, one level up from the
   3 files in `components/views/`): accepts `onBack: () => void`,
   `title: string`, and an optional `titleStyle?: CSSProperties` (used only
   by `RecipeDetailView` to carry its 28px/600 Display-role override).
   Renders a 3-column flex header — fixed 48px-wide left cell containing a
   circular (`shape="circle"`), `type="primary"` (accent green, matching
   `SearchFilterBar`'s established icon-button treatment), icon-only
   `Button` (`ArrowLeftOutlined` from `@ant-design/icons`, already a
   dependency) sized `{ width: 48, height: 48, minWidth: 48, padding: 0 }`
   with `aria-label="Back"`; a centered `<h2 className="text-white">`
   (`flex: 1, textAlign: 'center'`, merging in `titleStyle` when passed);
   and a matching empty 48px-wide right spacer cell so the fixed-width left
   button doesn't throw off the title's true centering. New
   `FullScreenHeader.test.tsx` covers title render, back-button accessible
   name/48px sizing, click-calls-onBack, and the `titleStyle` override.

2. **Wire all 5 views**: replace each file's inline header markup with
   `<FullScreenHeader onBack={...} title={...} />` (RecipeDetailView also
   passes `titleStyle={{ fontSize: 28, fontWeight: 600 }}`), drop the now-
   unused `Button` import in `RecipeDetailView.tsx` specifically (its only
   `Button` usage was the header — `AddEditIngredientView.tsx`,
   `AddEditRecipeView.tsx`, `CategoryManager.tsx`, `GlasswareManager.tsx`
   all keep their `Button` import since it's used elsewhere in each file).
   Update the 3 test files identified above whose back-button selectors
   would otherwise break.

Both tasks keep the existing 48px minimum touch-target convention and the
existing `type="primary"` accent-green (`#22c55e`) styling already
established by `SearchFilterBar`'s square Add button — no new color is
introduced.
