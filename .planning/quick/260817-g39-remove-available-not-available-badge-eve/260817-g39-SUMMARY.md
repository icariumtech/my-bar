# Quick Task 260817-g39: Remove AVAILABLE/NOT AVAILABLE badge, add available-only/show-all toggle Summary

**Removed the MakeableIndicator AVAILABLE/NOT AVAILABLE badge from Patron's browse card and detail screen, deleted the now-dead component, and added a bottom-pinned Eye/EyeOff availability toggle to TagRail that defaults to available-only and combines with the tag filter via AND.**

## Performance

- **Duration:** ~10 min
- **Tasks:** 2
- **Files modified:** 9 (2 deleted, 7 modified)

## Accomplishments
- TagRail.tsx gained a new exported `filterRecipesByAvailability(recipes, showAvailableOnly)` pure function (green-only when true, same-array-reference no-op when false) and a bottom-pinned `mt-auto` toggle button (Eye/EyeOff icon, AVAILABLE/ALL label, `aria-pressed`)
- RecipeBrowse.tsx now owns `showAvailableOnly` state (defaults `true`) and composes `filterRecipesByAvailability(filterRecipesByTag(allRecipes, selectedTagId), showAvailableOnly)` — both filters apply together (AND), never one overriding the other
- RecipeCard.tsx and RecipeDetail.tsx no longer render the MakeableIndicator badge; the header-row flex wrapper in RecipeCard.tsx (which existed only to lay the badge out beside the recipe name) was removed along with it
- MakeableIndicator.tsx and MakeableIndicator.test.tsx deleted — confirmed dead code, no remaining references anywhere in `apps/`
- D-44's missing-ingredient callout on RecipeDetail (the distinct "Not Available — {categories} missing." line) is untouched and still renders for red recipes with missing categories
- D-43's opacity-60 grayscale dimming is now the sole visual not-makeable signal on the browse list
