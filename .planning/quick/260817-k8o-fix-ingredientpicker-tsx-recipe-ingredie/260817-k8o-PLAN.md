<objective>
Fix IngredientPicker.tsx so its combined category/ingredient autocomplete actually filters the dropdown by the typed search text, matching the already-correct filtering behavior in CategoryPicker.tsx and GlasswarePicker.tsx.

Purpose: Currently `categoryOptions` and `ingredientOptions` are built by mapping the full `categories`/`ingredients` lists with no filter, so every category and ingredient is always shown regardless of what the owner types — only the "+ Add new ingredient" affordance reacts to search text. This breaks the "search-as-you-type" UX the picker is supposed to provide and makes it hard to find a specific ingredient/category once the list grows beyond a screenful.
Output: `IngredientPicker.tsx` filters both option lists by a case-insensitive substring match against `trimmed` before mapping to `{value, label}` options; `IngredientPicker.test.tsx` gains coverage proving non-matching options are excluded from the dropdown.
</objective>

Ingredient labels include the category name (`${i.name} (${i.categoryName})`) per the RESEARCH.md Pitfall 2 comment already in the file (lines 83-86) — filter on `i.name` only (not the composed label), matching how `hasExactIngredientMatch` already compares against `i.name` alone, not the full label.
