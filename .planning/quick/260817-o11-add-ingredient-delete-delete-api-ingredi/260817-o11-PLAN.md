<objective>
Add ingredient delete end-to-end: a `DELETE /api/ingredients/:id` route, a `useDeleteIngredient` mutation hook, and a Delete icon button on `IngredientRow` — mirroring the existing, already-shipped recipe-delete pattern (RECIPE-02: `RecipeRow.tsx` + `useDeleteRecipe`) exactly, so the Barback owner can remove a bottle from inventory the same way they already remove a recipe.

Purpose: Ingredient delete does not exist anywhere today (no route, no hook, no UI) even though recipe delete has shipped and works. The schema was deliberately designed for this: `recipeIngredients.ingredientId` has `onDelete: 'set null'` (confirmed in `apps/server/src/db/schema.ts:75`, NOT `'restrict'` like `categories`/`glassware`), so a recipe line locked to a specific ingredient degrades gracefully to category-only matching when that ingredient is deleted — no reference-count guard or 409 response is needed, unlike category/glassware delete.
Output: Owner can tap Delete on any ingredient row in Barback, confirm a named dialog, and have the bottle removed from inventory — recipes referencing it (if any) keep working via category-only fallback, and both the ingredients and recipes views resync automatically.
</objective>
