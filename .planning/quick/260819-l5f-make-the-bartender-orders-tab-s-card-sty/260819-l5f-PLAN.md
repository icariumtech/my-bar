<objective>
Restyle the Bartender Orders tab's card body so its structure/spacing/visual treatment matches the Recipes tab's cards exactly wherever the two share the same content, resolving the visual inconsistency the user flagged between the two tabs.

Purpose: Both tabs were redesigned onto antd `Card` in the same prior quick task (260818-uz8), and at the outer `Card` level (hoverable, cursor pointer, body padding 16, container gap-sm spacing) they already match — that part is not the problem. The divergence is entirely in the inner JSX row layout: RecipesTab pairs the recipe name with `MakeableStatusBadge` on one `flex justify-between items-center` top row, then the ingredient-names line below it (two rows total). OrdersTab instead paired name with elapsed-time on the top row and pushed `MakeableStatusBadge` onto its own separate row underneath, with the optional patronNames line and the ingredient-names line stacked after that (up to four rows) — a taller card with a differently-weighted top row is exactly what reads as "inconsistent" next to RecipesTab's cards in the same list-of-cards UI. This plan re-homes `MakeableStatusBadge` onto the shared top row (matching RecipesTab byte-for-byte in structure/class) and consolidates OrdersTab's two genuinely Orders-only pieces of content — elapsed time and the optional patronNames line — into one new secondary row, keeping the ingredient-names row identical to RecipesTab's. The Done button is NOT added to the list card itself: it remains reached via tapping into `RecipeOrOrderDetail`, exactly as today, since this is a pure visual/structural alignment and adding a second inline Done control would be a functional change, which is explicitly out of scope.
Output: `apps/bartender/src/components/OrdersTab.tsx` with a restructured Card body; `OrdersTab.test.tsx` still green (all pre-existing text-based assertions keep passing since only row structure changes, not text content); a human visual check confirming the two tabs now read as one consistent card style.
</objective>
